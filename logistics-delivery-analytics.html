How it was built

I loaded the Olist order and customer CSVs into PostgreSQL, checked identifiers, join coverage, and missing dates, and built a reporting view with one row per delivered order. Power BI imports that view and uses DAX measures that respond to report filters.

An order counts as on time when it arrives on or before the estimated delivery date. The rate uses delivered orders with both dates available. Delivery time runs from purchase to delivery, and average delay includes only late orders.

Data source · Olist Brazilian E-Commerce Public Dataset

Tools · PostgreSQL, SQL, Power BI, DAX

What the report shows

Of 96,470 evaluated orders, 6,534 arrived late, a late rate of 6.77%. São Paulo (SP) and Rio de Janeiro (RJ) had the largest counts of late orders. The state table pairs those counts with each state's late rate and average delay to help prioritize follow-up.

SQL behind the state comparison

SELECT
    customer_state AS state,
    COUNT(delivery_status) AS evaluated_orders,
    COUNT(*) FILTER (WHERE delivery_status = 'Late') AS late_orders,
    ROUND(
        100.0 * COUNT(*) FILTER (WHERE delivery_status = 'On time')
        / NULLIF(COUNT(delivery_status), 0), 2
    ) AS on_time_pct,
    ROUND(
        100.0 * COUNT(*) FILTER (WHERE delivery_status = 'Late')
        / NULLIF(COUNT(delivery_status), 0), 2
    ) AS late_rate_pct,
    ROUND(AVG(delay_days), 2) AS avg_delay_days
FROM olist.delivery_analysis
GROUP BY customer_state
ORDER BY late_orders DESC, state;
